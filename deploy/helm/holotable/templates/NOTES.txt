{{- if not (include "holotable.secretName" .) }}

WARNING: no credential source is configured.

  Neither secrets.existingSecret nor secrets.create is set, so the pod has no
  SESSION_SECRET and no DATABASE_URL. Its startup validation will refuse to
  boot and say so in the log — which is the intended behaviour, not a crash to
  debug. Create a Secret holding the credential environment and set
  secrets.existingSecret to its name. The chart README has all three wirings.
{{- end }}

{{- if or .Values.autoscaling.enabled (gt (int .Values.replicaCount) 1) }}

WARNING: this release runs more than one app replica.

  The poller is process-local: each replica polls every dashboard it has a
  subscriber for, so TimescaleDB sees the load multiplied, and two viewers of
  one dashboard can see different data. Safe horizontal scaling is
  https://github.com/jbouder/holotable/issues/40. Until it lands, keep
  replicaCount at 1 and autoscaling disabled.
{{- end }}

{{- if and .Values.podDisruptionBudget.enabled (eq (int .Values.replicaCount) 1) .Values.podDisruptionBudget.minAvailable (not .Values.autoscaling.enabled) }}

WARNING: a PodDisruptionBudget of minAvailable {{ .Values.podDisruptionBudget.minAvailable }} over a single
replica blocks voluntary disruption entirely: `kubectl drain` on this node will
wait forever. Either run more replicas (see above) or set
podDisruptionBudget.maxUnavailable: 1 instead.
{{- end }}
