## From a sentence to a live dashboard

<ol class="home-steps">
  <li>
    <strong>Describe it</strong>
    <span>“p95 latency by route for the last hour, red past 300 ms.”
    Holotable reads your source's catalog — tables and columns, metric names,
    log labels — so the model writes against what is really there.</span>
  </li>
  <li>
    <strong>Refine it</strong>
    <span>Ask for changes in the same chat — “make the third one a bar chart” —
    or edit any panel's query, layout and thresholds by hand. Every save is a
    version you can diff and restore.</span>
  </li>
  <li>
    <strong>Watch it live</strong>
    <span>Panels stream fresh rows over one connection, each on its own
    refresh cadence, with a shared time picker, variables and annotations
    across the whole dashboard.</span>
  </li>
</ol>

## Safe by construction

The model writes a **spec**, never the data. Every query it proposes, whether
SQL, PromQL or LogQL, is parsed and checked — read-only, catalog allowlist,
server-owned time window, row and point limits, and per-viewer row filters —
before it runs, and again on every save.
Connection details and credentials never leave the server.

## Try it in one command

```sh
docker run -p 3000:3000 ghcr.io/jbouder/holotable:quickstart
```

Open `http://localhost:3000`: a demo database, live sample
metrics and ready-made dashboards, with no account to create. Upload a CSV,
JSON or Excel file of your own and, when its columns fit, get a starter
dashboard built from them before you configure a model.
[Quick start](/getting-started/quick-start/)
